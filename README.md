# 教材征订小程序（任课老师 + 学生）

## 一、项目简介

传统教材征订多依赖班级统一收取纸质表格或群接龙，存在流程分散、信息易错、汇总困难、统计滞后等问题。本项目基于微信小程序原生框架，把「任务发布 — 教师填报 — 学生选购 — 审核汇总 — 数据导出」全流程线上化。

小程序端只承载**任课老师**与**学生**两个角色：教师按「课程 × 班级」填报教材明细，学生按班级教材清单完成选购；教材库维护、账号与组织管理、审核、统计与导出等功能在电脑端 Web 系统完成，超管 / 学院秘书 / 供货商登录小程序会看到「该身份请使用 Web 端」引导。

数据来自学校教材征订服务（Spring Boot + MySQL），小程序是纯客户端，不再使用本地模拟数据。按需求约定，本系统不含支付环节；消息提醒以应用内阻塞弹窗为主，订阅消息为已授权学生的额外提醒。

> 页面清单、里程碑、验收口径以 **[`docs/08-小程序端升级计划.md`](docs/08-小程序端升级计划.md)** 为准；接口契约唯一来源是 `textbook-order-server/API.md`。

## 二、核心功能

### 2.1 登录与会话

- 「学号/工号 + 密码」登录，错误按码分流（账号或密码不正确 / 账号已锁定 / 账号已停用 / 操作过于频繁）；
- 首次登录（`mustChangePassword`）强制走「首登校验 → 修改初始密码」，不可跳过：
  首选 `wx.login` 换 openid 完成校验，环境不支持时自动降级为「手机号后 4 位」；
- 登录态持久化：冷启动有有效会话直接进首页，不显示登录页；access 过期静默 refresh（并发 401 只触发一次），
  refresh 失效或账号停用才强制登出；
- 落地页按身份与权限码判定：任课老师 → 教师首页；学生 → 学生首页；
  超管/秘书/供货商 → 「该身份请使用 Web 端」；多角色可在「我的」页切换身份。

### 2.2 教师端

| 功能 | 说明 |
|------|------|
| 我的课程 | 本学期任课关系按「班级 → 课程」两级展示；无任课关系时给出空态提示 |
| 填报 | **明细行编辑器**：课程 × 班级 × 教材 × 数量逐行增删；教材支持关键词检索选择；提交为整单覆盖 |
| 字段审查回显 | 提交后服务端逐字段审查，未通过时顶部汇总「存在 N 项问题」并把错误定位到具体行（红字） |
| 补正 | 被驳回/字段审查未过 → 展示驳回理由 + 补正截止倒计时 + 「补正重提」；**窗口截止后补正窗口内仍可提交** |
| 提交记录 | 跨学期记录 + 审查状态轨迹（提交 → 系统字段审查 → 教材室内容审核 → 结果）；教师端不提供导出 |

### 2.3 学生端

| 功能 | 说明 |
|------|------|
| 教材选购 | 清单来自本班教师已审核通过的教材并集；必修默认勾选 1 本，可改数量或取消；已下架教材置灰不可选 |
| 数量 | 步进 1–9；不做上限预校验，超出班级人数由服务端回显提示 |
| 一人一本 | 勾选第 2 种时提醒；提交多种或清空全部选择时二次确认 |
| 提交确认 | 明细表 + 合计 + 底部固定小字「价格和版本以最终出版单位供应为准」；提交为覆盖语义 |
| 我的记录 | 「我的」页展示跨学期选购汇总（学期 / 状态 / 行数 / 册数 / 归属快照）；历史学期无明细端点，明细与金额在本学期选购页查看 |

### 2.4 通知

- 进入任一页面拉取未确认通知，有未确认则以**自绘阻塞弹窗**逐条展示（按时间倒序取最新 5 条），
  点「收到」完成确认后才放行；第 6 条起不阻塞，在「我的」页可查；
- 订阅授权在「收到」点击回调内请求（微信要求授权由用户点击触发）；模板未配置时降级为纯弹窗；
- 「我的」页提供待确认队列与全部通知。

## 三、技术实现要点

1. **原生框架，零第三方依赖**：WXML/WXSS/JS，无 npm 构建环节，导入即编译。
2. **数据层分层**（`utils/`）：
   - `config.js`：`baseUrl` 单点 + 超时 + 弹窗队列/数量上限等常量（切环境只改一处）；
   - `request.js`：`wx.request` Promise 封装、`{code,message,data}` 解包、204/空 body 归一、
     错误归一、页面级并发闸门、401 挂接；
   - `auth.js`：token 存取、单飞 refresh + 并发排队、401 三类语义、冷启动恢复、强制登出、落地分流；
   - `api.js`：19 个端点收敛（auth / me / window / student / teacher / notice），**页面只调这里**；
   - `format.js`：服务端 ISO 时间解析（兼容 6–7 位小数秒，规避 iOS `Invalid Date`）、
     以 `serverTime` 为锚点的倒计时、金额。
3. **组件化**：`components/window-status`（窗口三态 + 倒计时 + 60s 轮询）、
   `components/confirm-modal`（自绘确认弹层）、`components/notice-popup`（阻塞通知）。
4. **几个必须留意的口径**：
   - 倒计时一律用服务端 `serverTime` 求差，不信本地时钟；提交硬门禁是 `windowStatus==='open' && channelOpen===1`；
   - `mustChangePassword`/`firstLoginVerified` 在登录响应是布尔、在 `/api/me` 是 0/1，已统一归一；
   - refresh 会把 `currentRole` 重置为 `roles[0]`，因此 refresh 后重取 `/api/me` 并以服务端身份为准；
   - 原生小程序无 npm 构建，**不要用数组解构**（`const [a,b] = ...`）——会引入
     `@babel/runtime/helpers` 依赖并在运行时报错，改用下标取值。

## 四、使用说明

### 4.1 运行环境

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版，基础库 ≥ 2.30.0）；
2. 导入本目录，AppID 用测试号即可；
3. 后端启动后编译运行：本地联调 `utils/config.js` 的 `baseUrl` 指向 `http://localhost:8080/api`，
   并在开发者工具中关闭域名校验（已写入 `project.private.config.json`，该文件不入库）；
4. 试运行 / 移交时改 `baseUrl` 为 `https://<域名>/api`，并在微信后台配置合法域名（HTTPS 必开）。

### 4.2 演示账号

| 角色 | 工号/学号 | 密码 | 说明 |
|------|-----------|------|------|
| 任课老师 | `700101` | `Tea@12345` | 计算机学院，数据结构 / 软工2023-1（已有已通过填报） |
| 学生 | `20230101` | `Stu@12345` | 软工2023-1（已有选购记录） |
| 首登待改密 | `700102` | `700102` | 走「首登校验 → 改密」流程 |

登录页提供以上账号的快捷填充。多角色演示账号 `700103`（学院秘书 + 任课老师）可用于体验身份切换。

### 4.3 推荐演示路径

1. 以老师 `700101` 登录 → 我的课程 → 填报页（增删明细行、选教材、提交、查看字段审查回显）；
2. 「我的」→ 切换身份 / 通知确认 / 修改密码；
3. 退出后以学生 `20230101` 登录 → 选购页勾选与提交 → 首页查看提交状态 → 我的记录。

## 五、当前边界

- 异动申请、全部导出、通知管理、组织/账号/学期/教材库/统计管理**仅 Web 端**（小程序无对应权限）；
- 教师历史学期**只有汇总信息**，明细需在 Web 端查看（后端无历史学期明细端点）；
- 学生端不做数量上限预校验（接口不返回班级人数），超限由服务端回显；
- 教师端不展示金额合计（单价需额外检索才能取全，避免金额失真），按「行数 / 册数」计量；
- 订阅消息通道需后端配置微信密钥与模板 id；未配置时降级为纯弹窗（`utils/config.js` 的 `SUBSCRIBE_TEMPLATE_ID`）。
