# 教材征订小程序（MVP 演示版）

## 一、项目简介

传统教材征订多依赖班级统一收取纸质表格或群接龙，存在流程分散、信息易错、汇总困难、统计滞后等问题。本项目基于微信小程序原生框架开发了一套面向高校的教材征订系统，将「任务发布 — 学生勾选 — 数据汇总 — 结果导出」全流程线上化。

系统采用学生与教材管理员两种角色：学生登录后按所在班级完成教材勾选；教材管理员负责发布征订任务、维护教材与学生信息、查看征订统计并导出数据。按需求约定，本系统不含支付环节，消息推送能力预留接口、暂以站内信形式呈现。

当前为 MVP 演示版本，数据层采用本地模拟数据实现，功能流程与真实部署版本一致，可直接导入微信开发者工具运行体验。

> ⚠️ **本 README 描述的是 MVP 演示版现状。** 面向真实后端的改造计划（页面清单 / WBS / 工期 / 接口清单 / 验收口径）见 **[`docs/08-小程序端升级计划.md`](docs/08-小程序端升级计划.md)**（v1 · 2026-09-21）——涉及升级口径时，一律以该文档为准（下文第三节第 2 条、第五节的相关表述已被该文档修正）。

## 二、核心功能

### 2.1 登录鉴权

- 采用「学号（或教师工号）+ 姓名」双字段严格匹配在册名单，非在册人员无法进入系统；
- 登录后自动识别角色（学生 / 教材管理员），分别呈现对应的功能界面。

### 2.2 学生端

- 系统根据学号自动定位所在班级，带出与该班级关联的征订任务与教材清单；
- 教材支持勾选与数量调整，区分必修 / 选修（必修默认勾选）；
- 提交后如需变更，可在截止时间前修改并重新提交；
- 遵循「一人一本」征订原则：勾选多种教材时给予提醒，提交前二次确认（不强制限制）。
- 个人征订记录可随时查看，含教材明细与金额合计。

### 2.3 管理员端

| 功能 | 说明 |
|------|------|
| 征订任务发布 | 自定义任务名称与截止日期，按班级勾选征订范围，关联征订书目；支持任务截止 / 重新开放控制 |
| 教材信息管理 | 教材字段涵盖书名、ISBN、版次、作者、出版社、单价、课程名、选用教师、适用班级；支持逐条添加与批量导入 |
| 学生信息管理 | 支持批量导入与逐条维护，可按学号 / 姓名 / 班级检索 |
| 统计与导出 | 班级 / 专业 / 学院三级订书比例统计（条形图与饼图呈现）、教材征订数量与金额汇总、未提交学生名单（漏订催办）、征订明细一键导出 |

### 2.4 批量导入能力

- 支持**直接上传 Excel 文件（.xlsx）**导入：从微信会话中选择文件，系统内置轻量解析器直接读取，无需任何服务器参与；
- 提供**一键下载导入模板**（学生表：学号、姓名、学院、专业、班级；教材表：书名、ISBN、版次、作者、出版社、单价、课程名、选用教师、适用班级、必修），模板可转发至电脑填写；
- 教材导入兼容「含 ISBN」与「不含 ISBN」两种表格格式，系统自动识别；
- 学生导入格式为「学号 | 姓名 | 学院名称 | 专业名称 | 班级全称」，所属学院、专业、班级不存在时自动创建，无需预先维护组织数据；
- 导入过程内置查重机制：学号重复的记录自动跳过，且不产生冗余的组织数据；
- 备用方案：无文件场景下仍支持「Excel 复制粘贴」方式导入。

## 三、技术实现要点

1. **原生框架，零第三方依赖**：采用微信小程序原生 WXML/WXSS/JS 开发，无 npm 构建环节，项目导入即编译，部署成本低。
2. **数据层抽象**：全部业务逻辑收敛于 `utils/store.js`，页面仅依赖其函数签名。当前基于本地 Storage 实现。⚠️ **注意**：`store.js` 为**同步**实现（`wx.getStorageSync`），改为接口调用后必然变异步，页面**不能**零改动——实测全仓 69 处调用点需改 `await`。升级方案见 `docs/08-小程序端升级计划.md` §3.5。
3. **数据模型**：采用「学院 1—N 专业 1—N 班级 1—N 学生」的层级关联模型；班级建模为「专业 + 年级 + 班号」三元组，教材以 ISBN 作为唯一标识，参照高校教材管理系统的主流设计方案设计，结构清晰、便于扩展。
4. **批量导入的自动建链机制**：导入学生时按名称自动匹配并创建缺失的学院 / 专业 / 班级层级，且先查重后建链，保证增量导入不会产生冗余数据。
5. **统计图表**：三级订书比例通过数据聚合动态计算，饼图基于 Canvas 2D 接口原生绘制，未引入第三方图表库。
6. **界面规范**：建立统一的设计规范（色彩令牌、圆角与阴影体系、组件化样式、触控按压反馈），保证各页面视觉与交互的一致性。

## 四、使用说明

### 4.1 运行环境

1. 安装[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)（稳定版）；
2. 导入本目录（`textbook-order-mp`），AppID 使用测试号即可（已预置游客模式配置）；
3. 编译后在模拟器体验，或点击「预览」生成二维码进行真机体验。

### 4.2 演示账号

| 角色 | 账号 | 姓名 |
|------|------|------|
| 学生（计算机科学与技术 2024 级 1 班） | `20240101` | 张敬 |
| 教材管理员 | `T0001` | 王教材 |

登录页提供演示账号快捷填入。演示数据预置了 3 个学院、5 个班级、26 名学生、12 种教材及两个征订任务（含部分已提交记录），以便直接查看统计效果。

### 4.3 推荐演示路径

在同一设备上切换账号即可演示完整业务闭环：

1. 以学生身份登录 → 勾选教材 → 提交征订；
2. 退出后以管理员身份登录 → 查看统计页（比例实时更新）→ 执行数据导出。

> 说明：模拟数据存储于设备本地，同一设备上的不同角色共享数据，因此切换账号可看到彼此操作的结果；不同设备间的数据相互独立。

## 五、当前版本边界与后续规划

**当前边界**（MVP 范围约定）：

- 数据为本地模拟数据，重置小程序即恢复初始种子数据；
- Excel 导入依赖从微信会话选取文件（wx.chooseMessageFile），超大表格的解析性能未做专项优化；
- 消息提醒为站内信占位，订阅消息推送能力待确认后接入；
- 按需求约定，本期不包含支付环节。

**后续规划**：已收敛为可执行计划，见 **[`docs/08-小程序端升级计划.md`](docs/08-小程序端升级计划.md)**（MP 线 4 周 · M1–M5 + M6 备案/上架）。要点：

1. **删除 MVP 管理端链路**：4 个 admin 页 + `pages/messages` 退场（小程序 = 任课老师 + 学生，管理功能一律走 Web 端），同步删除 `utils/{mock,export,xlsx-lite}.js` 与 `utils/vendor/pako.min.js`；
2. **数据层替换**：`utils/store.js` → `utils/request.js` + `utils/auth.js` + `utils/api.js`（异步化，页面调用点同步改造）；
3. **新增教师端**：我的课程 / 填报（字段审查回显 + 补正入口）/ 提交记录 三页；
4. **通知通道**：阻塞弹窗（队列上限 5 条）+ 「收到」点击回调内请求订阅授权；订阅消息仅覆盖已绑定 openid 的学生，模板类目不可报时降级为纯弹窗；
5. 站内信（`pages/messages`）已按决策否决，由阻塞弹窗 + 「我的」页通知承接。
